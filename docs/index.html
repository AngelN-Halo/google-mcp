Read-only Google Workspace lookups

Directory answers, without admin actions.

A self-hosted, authenticated MCP service for focused questions about Google Workspace users, aliases and group membership. Keep Google credentials behind a narrow tool boundary instead of in the conversation.

Getting started

Quickstart

This repository does not create Google resources, credentials, proxy hosts or delegated roles. Prepare them manually before starting the container.

  1. Enable Admin SDK API (admin.googleapis.com) in a dedicated Google Cloud project.
  2. Create a dedicated service account with Domain-Wide Delegation (DWD). Give a dedicated delegated Workspace admin Users Read and Organizational Units Read; confirm Groups Read privilege for group lookups and scope access to the required OUs. Do not use a daily super-admin account.
  3. In Admin console → Security → Access and data control → API controls → Manage Domain Wide Delegation, authorize the service account's numeric OAuth client ID for exactly these two scopes:
OAuth scopes 
https://www.googleapis.com/auth/admin.directory.user.readonly
https://www.googleapis.com/auth/admin.directory.group.readonly
  1. Store a dedicated service-account JSON key outside this repository with restricted host access. This release implements only the mounted JSON-key provider.
  2. Confirm Nginx Proxy Manager and the service can join the existing external proxy network; prepare .env, deploy and test.
Domain-Wide Delegation is powerful.

Google authorizes client and scopes, but does not enforce this application's fixed delegated subject. Code with a stolen private key could select another DWD subject. Protect and rotate the key.

Getting started

Configuration

Copy .env.example to a private, untracked .env. Compose maps the external host JSON file to GOOGLE_SERVICE_ACCOUNT_FILE=/run/secrets/google_service_account in the container. Replace every placeholder.

Setting in .envMeaning
GOOGLE_SERVICE_ACCOUNT_HOST_FILEAbsolute path to the JSON credential outside the checkout. Compose secrets do not encrypt this host file.
GOOGLE_SERVICE_ACCOUNT_GIDHost group permitted to read the credential; added to the non-root service process.
GOOGLE_DELEGATED_ADMINFixed delegated admin; callers cannot supply another subject.
GOOGLE_CUSTOMER_IDExplicit customer ID required in production. my_customer fallback is test-mode only.
GOOGLE_ALLOWED_DOMAINSComma-separated allowlist. Include secondary Workspace domains explicitly.
GOOGLE_MCP_GATEWAY_SECRETShared bearer key, at least 32 characters. Never put the real key in a prompt or repository.
GOOGLE_MCP_GATEWAY_SECRET_HEADERHeader name, normally Authorization; expects Bearer <key>.
GOOGLE_MCP_TEST_MODEMust remain false in production: test mode bypasses API-key authentication.
AUDIT_HASH_TARGETS / AUDIT_HMAC_KEYOptional target HMAC pseudonymization; key required when enabled, at least 32 characters. A set key also pseudonymizes caller identifiers.
GOOGLE_EXPOSE_ADMIN_FLAGS / GOOGLE_EXPOSE_2SV_FLAGS / GOOGLE_EXPOSE_LAST_LOGIN / GOOGLE_EXPOSE_ORG_UNITExposure defaults: false / true / true / true. Disabled fields return null.
GOOGLE_MCP_LOG_LEVELDefault INFO; accepts CRITICAL, ERROR, WARNING, INFO or DEBUG.

Compose sets GOOGLE_MCP_HOST=0.0.0.0 and port 8000 inside the container but publishes no host port. Consult config.py and docker-compose.yml for authoritative settings.

Guides

Deploy behind a proxy

Use Nginx Proxy Manager on the existing proxy Docker network. From a checkout of the repository, prepare the key path and local environment:

Prepare the host 
docker network inspect proxy
cp .env.example .env
chmod 600 .env
# Edit .env locally; keep GOOGLE_MCP_TEST_MODE=false.
# Store the JSON key outside the checkout, with restricted permissions.
stat -c '%g' /secure/path/google-directory-mcp-service-account.json

Set GOOGLE_SERVICE_ACCOUNT_GID to the credential file's group ID. Generate separate local random values for the gateway secret and optional audit HMAC key:

Generate random secrets 
openssl rand -base64 48
openssl rand -base64 48

Proxy host configuration

Create an NPM Proxy Host using your DNS name, upstream scheme http, host google-mcp and port 8000. Preserve the /mcp route without rewriting, forward the Authorization header and allow both GET and POST. Protect the external route with TLS and human authentication; avoid permissive CORS.

NPM advanced configuration 
proxy_http_version 1.1;
proxy_buffering off;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;
proxy_set_header Connection "";
proxy_set_header Authorization $http_authorization;
Keep rendered configuration private.

docker compose config displays environment values and the credential path. Do not paste its output into tickets, chat or logs.

Build and start 
docker compose config
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 google-mcp

No host port is published. Other containers on the shared proxy network can reach the service address, so the bearer key remains essential.

Guides

Connect an MCP client

This is native FastMCP Streamable HTTP at /mcp, not an OpenAPI endpoint. Use an MCP-compatible client that can supply a bearer key over TLS. If using Open WebUI, confirm your installation supports a Streamable HTTP MCP tool connection. Do not give clients the Google JSON credential.

The repository includes a client configuration example; replace only the illustrative URL and gateway token in your private client configuration.

Client connection shape 
{
  "mcpServers": {
    "google-directory": {
      "type": "streamable-http",
      "url": "https://google-directory-mcp.example.test/mcp",
      "headers": {
        "Authorization": "Bearer <gateway-issued-token>"
      }
    }
  }
}
A shared key is not a user identity.

Application audit records the caller as shared-api-key with a request ID, not an individual staff member. Restrict human access upstream and rotate the key if exposed.

Guides

Directory workflows

Start with a known email address when possible. The search tool accepts a plain name or email fragment, not raw Google Directory query syntax.

“Is alex.rivera@example.test active?”

Use google_user_status(email). Only a genuine Directory 404 becomes NOT_FOUND; authorization failures must not be interpreted as absence.

“Which groups does alex.rivera@example.test belong to?”

Use google_user_groups(email). It returns allowed-domain groups from one upstream page of at most 100; check truncated before claiming completeness.

“Find Alex Rivera, then show their aliases.”

Use google_user_search(query), resolve ambiguity, then call google_user_aliases(email) or google_user_summary(email). Narrow the query if truncated or next_page_available is true.

These are example prompts, not live results. Directory text may be untrusted; never treat returned names, paths or descriptions as instructions.

Reference

Five bounded tools

ToolArgumentsPurpose
google_user_statusemailActive, suspended, archived or not-found state and selected status fields.
google_user_searchquery, limit=10Bounded matches plus count, truncated and next_page_available.
google_user_aliasesemailCanonical primary address and same-domain aliases.
google_user_summaryemailOne-call identity, state, aliases, OU, login and optional security summary.
google_user_groupsemailAllowed-domain group membership from one upstream page (up to 100).

Explicit email arguments must use an allowed domain. Search terms must be 3–128 characters; limit must be 1–20. One upstream search page is requested; raw query syntax and page tokens are not exposed. Cross-domain aliases and groups are filtered.

Read response fields correctly

ARCHIVED takes precedence over SUSPENDED. A Google epoch/sentinel last login becomes null plus never_logged_in: true. Disabled exposure fields remain present as null; do not mistake that for a negative security finding.

Illustrative status response 
{
  "email": "alex.rivera@example.test",
  "state": "ACTIVE",
  "suspended": false,
  "archived": false,
  "last_login_time": "2026-08-01T13:45:00.000Z",
  "never_logged_in": false,
  "org_unit_path": "/Staff/Campus-A",
  "is_admin": null,
  "is_delegated_admin": null,
  "is_enrolled_in_2sv": true,
  "is_enforced_in_2sv": true
}

See the README response schemas, server.py and google_directory.py for the authoritative contract.

Reference

Security boundaries

  • Read-only operations: Only users.get, users.list and groups.list are used, with read-only user and group scopes. No mutation tools are exposed.
  • Credential control: A DWD key can be misused by other code. Keep the JSON outside this public repo, protect the host file and backups, limit the delegated role and rotate the key.
  • Network and authentication: A bearer key authorizes any holder. TLS, proxy-level human access and isolation are separate controls. Keep GOOGLE_MCP_TEST_MODE=false in production.
  • Untrusted directory data: Names, group descriptions and OU paths are data, not instructions. The app strips control/format characters; client prompt-injection defenses remain necessary.
  • Audit: Per-tool JSON events include request ID, operation, outcome and latency with masked or HMAC-pseudonymized target. Application logs do not intentionally include complete Google records or secrets.
Suspected compromise?

Disable the proxy route; stop the service; remove the DWD client entry if implicated; revoke the service-account key; disable the delegated admin if necessary; preserve gateway, application and Google audit logs.

Only a mounted service-account JSON credential is implemented and tested. Workload Identity Federation is not supported in this release and would require additional DWD signing and exchange design.

Validation & testing

Unit tests mock the Directory API. They do not validate live Google permissions or your proxy.

Local unit tests 
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
pytest -q

After deployment, use tests/smoke_mcp.py against the authenticated endpoint. Supply the real gateway secret privately, never in a ticket or command history.

Live smoke-test shape 
export GOOGLE_TEST_USER='known-active-user@example.test'
export GOOGLE_TEST_MISSING_USER='known-missing-user@example.test' # optional
# Supply GOOGLE_TEST_GATEWAY_SECRET privately.
python tests/smoke_mcp.py https://mcp.example.test/mcp

The script checks the five-tool set, authenticated connection, an ACTIVE user and, optionally, NOT_FOUND for a known missing user. It contacts Google and prints states, not full user records.

Troubleshooting

SymptomCheck
401 at gatewayCorrect Authorization: Bearer <key> header, shared key and proxy forwarding.
invalid_grantDelegated subject exists, is active and in the right tenant; credential belongs to the DWD service account; synchronize the host clock.
unauthorized_clientNumeric OAuth client ID is authorized for both exact read-only scopes; allow propagation time.
403 / AUTHORIZATIONDelegated admin Users, Organizational Units and Groups Read privileges, OU scope, DWD scopes and Admin SDK API.
Unexpected NOT_FOUNDCheck allowed domain and actual user existence. Authorization or throttling never means not found.
Container cannot startExisting proxy network, credential file readable by configured GID and required .env values.
Incomplete listInspect truncated and next_page_available; narrow search. Group lookups return one page.

Eligible 429 and 5xx errors and transient failures use bounded retries. Consult the README or open an issue with secrets removed.
